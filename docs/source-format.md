# Source format of a pack

Everything a pack ships, except its `descriptor.mod` and `thumbnail.png`, is generated by `build.ps1 -Generate` from `source/<pack>/` and `data/`. This page describes those files and the switches that write them. `build.ps1 -Check` enforces every rule here. Engine behaviour is cited from the Manager's knowledge register, never restated.

## `source/<pack>/leaders.json`

Hand-written by the pack's agents.

```json
{
    "pack": "finland",
    "tag": "FIN",
    "prefix": "lp_fin",
    "displayName": "Finland",
    "leaders": [
        {
            "key": "einar_vihma",
            "name": "Einar Vihma",
            "mode": "new",
            "sameAs": [],
            "role": "corps_commander",
            "skill": 3,
            "attack": 3,
            "defense": 2,
            "planning": 2,
            "logistics": 2,
            "traits": ["infantry_officer"],
            "factSheet": "einar_vihma",
            "portrait": {
                "photo": "vihma",
                "role": "Finnish general",
                "headwear": "wearing a soft grey Finnish M36 field cap with a small round cockade",
                "uniform": "grey field uniform with collar patches",
                "avoidHeadwear": "peaked cap, visor cap, helmet",
                "notes": "",
                "born": 1894,
                "photoYear": 1943
            }
        },
        {
            "key": "harald_ohquist",
            "name": "Harald Ohquist",
            "mode": "addRole",
            "target": "FIN_harald_ohquist",
            "sameAs": [],
            "role": "corps_commander",
            "skill": 3,
            "attack": 2,
            "defense": 3,
            "planning": 3,
            "logistics": 2,
            "traits": [],
            "factSheet": "harald_ohquist",
            "portrait": { "photo": "ohquist", "role": "Finnish general", "headwear": "bareheaded", "uniform": "grey general's uniform", "avoidHeadwear": "cap, hat, helmet", "notes": "", "born": 1891, "photoYear": 1939 }
        },
        {
            "key": "hugo_osterman",
            "name": "Hugo Osterman",
            "mode": "skip",
            "reason": "A field marshal in Road to 56 (FIN_hugo_osterman); vanilla keeps him an advisor and addRole would duplicate him there."
        }
    ]
}
```

| Field | Rule |
|---|---|
| `pack`, `tag`, `prefix` | The pack key, the country tag, and `lp_` with the tag in lower case. The prefix never changes after a release. |
| `key` | Lower-case letters, digits and underscores; unique in the pack. It names the fact-sheet section, the photo and portrait records, and the generated ids. |
| `name` | The leader's name in English letters as the game should show it. Plain ASCII punctuation, no double quote, none of `[`, `]`, `$`, the section sign, the pound sign or `#`, and no `|` (it would split a row of the wiki table). |
| `mode` | `new`, `addRole` or `skip` (below). |
| `sameAs` | Required for `new` and `addRole` leaders; `[]` when the person has no other id. Every id the same person has in vanilla or in a supported mod, from the snapshot. A `new` leader is recruited only while the country holds none of them [SCR-035]: the `limit` holds one `NOT = { has_character = <id> }` line per id. An empty list writes no guard, never an empty `NOT = { }` [CRASH-007]. |
| `target` | `addRole` only: the existing character id that gets the role. |
| `role` | `corps_commander`, `field_marshal` or `navy_leader`. |
| `skill` and the attribute skills | Army roles: `attack`, `defense`, `planning`, `logistics`. Navy: `attack`, `defense`, `maneuvering`, `coordination`. Within `data/stat-bands.json` [CHR-006] [CHR-012]. |
| `traits` | Only traits vanilla gives a unit leader of that kind at the start, shared or of the pack's own country (`data/<pack>/start-traits.json`). |
| `factSheet` | The section `## <key>` of `source/<pack>/fact-sheets.md` with the sourced facts behind the leader and his stats. |
| `portrait` | `photo`: a key of `photos.json`. `role`, `headwear`, `uniform`, `avoidHeadwear`, `notes` go into the portrait prompts as written; naming the headwear is what keeps it. An empty `headwear` is a warning of `-Check`, not an error. `born` and `photoYear`, four-digit years (the leader's birth year from the dossier, the photo's year from its Commons page): their difference is the age cue of the prompt, which keeps the painted face from coming out too young; either missing is a warning of `-Check`; a value that is not a four-digit year, a photo year before the birth year, or years that give an age outside 15 to 100 (the range the Manager's `-Age` takes) an error. Optional, for a rejected round: `colourSeed`, a whole number from 0 up (absent: 1), the seed of the colouring step; `facePass`, `true` or `false` (absent: `true`), whether the face detail pass runs. `-Check` fails on any other value. |
| `reason` | `skip` only: why the leader is left out, with the id that already covers him. `-Check` fails when the reason names no character id of the snapshot. |

### Modes

- `new`: a character `<prefix>_<key>` in a `characters = { }` block [CHR-001], recruited from `on_startup` [CHR-003] [SCR-007] behind the `sameAs` guard. Each recruitment writes one warning line to `error.log` [CHR-014]. Works only in a new game [SCR-077].
- `addRole`: in `on_startup`, inside `if = { limit = { has_character = <target> } }`, the target gets the role and the large portrait, behind a guard on the role it already has: `is_army_leader` for an army role [SCR-103], `is_navy_leader` for a navy role [SCR-061]. The advisor role and its small portrait stay [CHR-013]. Road to 56 already makes some advisors leaders [RT56-011]; the guard skips them there.
- `skip`: nothing is generated. The leader stays in the file so that the research is not done again.

`-Check` compares each leader with the snapshot (`data/<pack>/game-characters.json`): a `new` leader's name or `sameAs` ids must not belong to a unit leader of vanilla or Road to 56; an `addRole` target must exist in vanilla with an advisor role and no unit-leader role of the same kind; every id in `sameAs` and `target` must exist in the snapshot.

## `source/<pack>/fact-sheets.md`

One section per leader, `## <key>`, with the facts behind the leader, his role and his stats, each with its source URL.

## `source/<pack>/workshop-intro.bbcode`

The opening of the pack's Workshop description in Steam BBCode. `-Generate` adds the leader list, a sentence that the portraits are AI-assisted repaints of period photographs with a link to the pack's wiki page for the photo credits, and the author's other mods (`data/workshop.json`).

## `source/<pack>/photos.json`

Written only by `build.ps1 -FetchPhoto -Pack <pack> -File "File:<Commons title>" -Key <photo key> [-DryRun]`. The licence gate is Event Packs': public domain with a `PD-` template stating why, CC0, or CC BY with a named author; it refuses a file tagged for deletion or dispute, a file that is not a picture, a download outside Wikimedia's servers, and a picture under 300 px on its shorter side. The download is kept in `sources-cache/<pack>/` (git-ignored). Each row keeps the Commons title and page, the download URL and its SHA-256, author, credit, licence, licence URL, Commons restrictions, the original size and the fetch date. `-Check` derives the licence category from the recorded Commons code again and compares the hash with the cached download when it is there; `-Audit` reads every licence from Commons again and warns about one read more than 180 days ago.

## `source/<pack>/portraits.json` and `source/<pack>/portraits/<key>.png`

Written only by `-MakePortraits` and `-ApplyPortraitReview`. One entry per leader:

```json
{
    "leaders": {
        "einar_vihma": {
            "rounds": [
                {
                    "round": 1,
                    "date": "2026-11-01",
                    "seeds": [1, 2, 3, 4],
                    "settings": { "role": "Finnish general", "headwear": "...", "uniform": "...", "avoidHeadwear": "...", "notes": "", "colourSeed": 1, "facePass": true, "born": 1894, "photoYear": 1943, "age": 49, "ageSent": true },
                    "run": "C:\\dev\\Hearts of Iron IV Modding Manager\\Artifacts\\portraits\\lp_fin_einar_vihma\\round-1\\portrait-run.json",
                    "recipe": { "steps": [ { "template": "K1", "sha256": "..." } ], "gradeStrength": 0.6, "facePass": true },
                    "candidates": [ { "seed": 1, "file": "...\\final\\A3_s1.png", "sha256": "...", "likeness": 0.31 } ],
                    "decision": { "pick": 2 }
                }
            ],
            "chosen": { "round": 1, "seed": 2, "file": "source/finland/portraits/einar_vihma.png", "sha256": "..." }
        }
    }
}
```

- `-MakePortraits -Pack <pack> [-Leader <key>] [-StartComfyUI]` makes one new round of 4 candidates for every `new` and `addRole` leader that has no `chosen` portrait, through the Manager's `New-HoiPortrait.ps1` (skill `hoi4-leader-portraits`) with the photo's cached download and the `portrait` fields; `born` and `photoYear` go as `-Age`, their difference, when both are set and the Manager's script takes the parameter; a Manager without it gets a `[WARN]` line and no age. The round's `settings` keep `born`, `photoYear` and `age` (`null` when unknown) and `ageSent`, whether the age reached the Manager. The recipe steps and candidate file names are whatever the Manager's recipe of the day writes (`A3_s1.png` until its round 6 recipe lands, `A4_s1.png` after). The seeds of round `n` are `4n-3` to `4n`. With `-StartComfyUI` it starts ComfyUI once for the whole batch and stops it at the end, also after an error; a ComfyUI it did not start is left running.
  - `-Leader <key>` makes a round for that leader only, also when he has a `chosen` portrait already; a later pick replaces it.
  - A leader whose latest round has no decision yet is skipped (with `-Leader`, exit 1): the owner reviews first.
- `-ApplyPortraitReview -Pack <pack> -Leader <key> -Pick <seed>` records the owner's pick on the latest round and copies that candidate to `source/<pack>/portraits/<key>.png` with its SHA-256. `-Reject "<reason>"` records the rejection on the latest round; the reason is what the next round must change. A round that has a decision cannot be decided again; a new round can.
- The record's shapes:
  - `decision` is `null` while the round waits, `{ "pick": <seed> }` or `{ "reject": "<reason>" }`.
  - `chosen` is `null` until the first pick.
  - `run` and each candidate's `file` are absolute paths in the Manager's `Artifacts/portraits/<prefix>_<key>/round-<n>/` (git-ignored, on the machine that made them). The Manager numbers its `round-<n>` folders by itself; the pack's `round` is the one that counts, and the two can differ.
- The chosen PNG is committed: generation is not reproducible across ComfyUI versions and GPUs.

## `source/<pack>/review.json` and the review page

The owner decides a round on a published review page rather than in the chat. `build.ps1 -ReviewPage -Pack <pack>` writes `scratch/review/<pack>/portrait-review.html` (git-ignored) from `tools/review-page-template.html` and `tools/review_page.py`, with one section for each leader whose latest round has no decision: the photo, the coloured photo, the previous round's decision, and the 4 candidates at the game's 156x210 and at three times that. With no round to review it writes nothing and exits 0.

- The agent publishes the page with the Artifact tool, with the capabilities the command prints: `{"db": {"rules": [{"path": "reviews", "read": "view", "write": "owner"}]}, "user": {}}`. Only the owner can decide; anyone the page is shared with can look.
- The first publish of a pack is recorded with `-ReviewPage -Pack <pack> -PageUrl <claude.ai artifact URL>`, which writes `source/<pack>/review.json`:

```json
{ "pageUrl": "https://claude.ai/artifact/...", "recorded": "2026-11-01" }
```

- Later rounds republish to the same URL, so the owner keeps one bookmark per pack.
- Each decision is a document of the page's `reviews` collection, named `<leader key>-r<round>`:

```json
{ "leader": "einar_vihma", "round": 1, "decision": "pick", "seed": 2, "reason": "", "decidedAt": "2026-11-01T12:00:00Z" }
```

  `decision` is `pick` (with `seed`, `reason` empty) or `reject` (with `reason`, `seed` null). The agent reads the collection with ArtifactData and applies each document with `-ApplyPortraitReview`, so `portraits.json` stays the record; the page only carries the owner's choice.
- Without the page's database the owner copies the decisions from the page as text lines, `<key> round <n>: pick <seed>` or `<key> round <n>: reject "<reason>"`.

## `source/<pack>/converted.json`

Written only by `-ConvertPortraits -Pack <pack> [-Force]`: for each DDS of the pack, what it was built from.

```json
{
    "portraits": {
        "gfx/interface/ideas/lp_fin_einar_vihma_small.dds": { "leader": "einar_vihma", "kind": "small", "chosenSha256": "...", "cardSha256": "...", "ddsSha256": "..." },
        "gfx/leaders/FIN/lp_fin_einar_vihma.dds": { "leader": "einar_vihma", "kind": "large", "chosenSha256": "...", "cardSha256": "", "ddsSha256": "..." }
    }
}
```

- `chosenSha256` is the chosen PNG's SHA-256 from `portraits.json`; `cardSha256` the SHA-256 of `data/portrait-card.json` with its line ends as LF (small cards only); `ddsSha256` the DDS as written.
- `-ConvertPortraits` skips a DDS whose three hashes are current, and converts it again with `-Force`.
- `-Check` fails on a DDS that is missing or of the wrong size, has no record, differs from its recorded hash, or was built from another chosen PNG or another card file; and on a record of a DDS no leader has.
- The small card needs the Modding Manager and the ComfyUI venv of its `Config/comfyui.json`: the crop of the photo window runs the Manager's `Measure-PortraitFaces.py crop` there. Without them `-ConvertPortraits` converts the large portraits and ends with exit 1.

## `data/`

| File | Content |
|---|---|
| `data/<pack>/game-characters.json` | Written by `-RefreshGameData -Pack <pack>` (needs the game): the country's characters in vanilla and in Road to 56, with ids, names, roles and slots. `-Check` and CI read this file, never the game. Refresh it before each release [RT56-011]. |
| `data/<pack>/start-traits.json` | Written by `-RefreshGameData -Pack <pack>`: per role kind (`army`, `navy`), every trait a vanilla unit leader of that kind has at the start in any country, except a trait named after a country (an upper-case prefix such as `JAP_`), which is kept only when a character of the pack's own tag has it. |
| `data/stat-bands.json` | Hand-written: the start ranges of `skill` and the attribute skills per role kind [CHR-006] [CHR-012]. |
| `data/workshop.json` | The wiki address and the author's other mods, shared by every pack. |
| `data/portrait-card.json` | The small card's geometry and the face position inside its photo window [CHR-005]; read by the converter. The owner approved these values: they change only on the owner's word. |
| `data/thumbnail.json` | The Workshop thumbnail, shared by every pack: `background` (a loading screen's path under the game root, read at render time and never copied into the repository), `crop`, `blur` and `scrim`; and per pack under `packs.<pack>.portraits` the 2 or 3 leader keys whose chosen portraits the thumbnail shows, left to right. Read by the release skill; changes only on the owner's word. |

`game-characters.json`, `start-traits.json` and `portrait-card.json` are protected from hand edits by the project hook.

## Generated files

| File | From |
|---|---|
| `packs/<pack>/common/characters/<prefix>_characters.txt` | the `new` leaders, with their role, stats, traits and portraits. A navy leader names the same sprites under `army` and `navy` [CHR-015]. |
| `packs/<pack>/common/on_actions/<prefix>_on_actions.txt` | one `on_startup` block: the guarded recruitments and the `addRole` blocks [SCR-007] [SCR-008] |
| `packs/<pack>/interface/<prefix>_portraits.gfx` | a large and a small sprite per `new` leader, a large one per `addRole` leader [SGUI-028] |
| `packs/<pack>/gfx/leaders/<TAG>/<prefix>_<key>.dds` | `build.ps1 -ConvertPortraits`: 156x210 uncompressed 32-bit DDS [CHR-004] [SPR-009] |
| `packs/<pack>/gfx/interface/ideas/<prefix>_<key>_small.dds` | `build.ps1 -ConvertPortraits`: the 65x67 code-drawn card with a crop of the chosen portrait [CHR-005] |
| `packs/<pack>/localisation/<language>/<prefix>_l_<language>.yml` | the `new` leaders' names in all ten languages [LOC-017], UTF-8 with BOM [LOC-001] |
| `packs/<pack>/WORKSHOP_DESCRIPTION_GUIDELINES.md` | intro, leader list, the AI-assisted portrait sentence with the wiki link, other mods |
| `wiki/Commanders-Pack-<Country>.md` | the leader table with each photo's source, licence (CC BY linked), author, and "AI-assisted repaint" |

The characters file and the localisation files are written only when the pack has a `new` leader, the on_actions file and the `.gfx` only when it has a `new` or `addRole` leader; a pack without leaders holds only its descriptor, thumbnail and Workshop description.

Nothing else may sit in `packs/<pack>/`: `-Check` fails on any other file there. `build.ps1 -PreviewPortraits -Pack <pack>` writes PNG copies of the converted portraits and a sheet to `scratch/preview/<pack>/`.

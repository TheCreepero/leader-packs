# Source format of a pack

Everything a pack ships, except its `descriptor.mod` and `thumbnail.png`, is generated by `build.ps1 -Generate` from `source/<pack>/` and `data/`. This page describes those files and the switches that write them. `build.ps1 -Check` enforces every rule here. Engine behaviour is cited from the Manager's knowledge register, never restated.

## `source/<pack>/leaders.json`

Hand-written by the pack's agents.

```json
{
    "pack": "finland",
    "tag": "FIN",
    "prefix": "lp_fin",
    "displayName": "Finland",
    "leaders": [
        {
            "key": "einar_vihma",
            "name": "Einar Vihma",
            "mode": "new",
            "sameAs": [],
            "role": "corps_commander",
            "skill": 3,
            "attack": 3,
            "defense": 2,
            "planning": 2,
            "logistics": 2,
            "traits": ["infantry_officer"],
            "factSheet": "einar_vihma",
            "portrait": {
                "photo": "vihma",
                "role": "Finnish general",
                "headwear": "wearing a soft grey Finnish M36 field cap with a small round cockade",
                "uniform": "grey field uniform with collar patches",
                "avoidHeadwear": "peaked cap, visor cap, helmet",
                "notes": "",
                "born": 1894,
                "photoYear": 1943
            }
        },
        {
            "key": "harald_ohquist",
            "name": "Harald Ohquist",
            "mode": "addRole",
            "target": "FIN_harald_ohquist",
            "sameAs": [],
            "role": "corps_commander",
            "skill": 3,
            "attack": 2,
            "defense": 3,
            "planning": 3,
            "logistics": 2,
            "traits": [],
            "factSheet": "harald_ohquist",
            "portrait": { "photo": "ohquist", "role": "Finnish general", "headwear": "bareheaded", "uniform": "grey general's uniform", "avoidHeadwear": "cap, hat, helmet", "notes": "", "born": 1891, "photoYear": 1939 }
        },
        {
            "key": "hugo_osterman",
            "name": "Hugo Osterman",
            "mode": "skip",
            "reason": "A field marshal in Road to 56 (FIN_hugo_osterman); vanilla keeps him an advisor and addRole would duplicate him there."
        }
    ]
}
```

| Field | Rule |
|---|---|
| `pack`, `tag`, `prefix` | The pack key, the country tag, and `lp_` with the tag in lower case. The prefix never changes after a release. |
| `key` | Lower-case letters, digits and underscores; unique in the pack. It names the fact-sheet section, the photo and portrait records, and the generated ids. |
| `name` | The leader's name in English letters as the game should show it. Plain ASCII punctuation, no double quote, none of `[`, `]`, `$`, the section sign, the pound sign or `#`, and no `|` (it would split a row of the wiki table). |
| `mode` | `new`, `addRole` or `skip` (below). |
| `sameAs` | Required for `new` and `addRole` leaders; `[]` when the person has no other id. Every id the same person has in vanilla or in a supported mod, from the snapshot. A `new` leader is recruited only while the country holds none of them [SCR-035]: the `limit` holds one `NOT = { has_character = <id> }` line per id. An empty list writes no guard, never an empty `NOT = { }` [CRASH-007]. |
| `target` | `addRole` only: the existing character id that gets the role. |
| `role` | `corps_commander`, `field_marshal` or `navy_leader`. |
| `skill` and the attribute skills | Army roles: `attack`, `defense`, `planning`, `logistics`. Navy: `attack`, `defense`, `maneuvering`, `coordination`. Within `data/stat-bands.json` [CHR-006] [CHR-012]. |
| `traits` | Only traits vanilla gives a unit leader of that kind at the start, shared or of the pack's own country (`data/<pack>/start-traits.json`). A trait Road to 56 does not define gets a `-Check` warning; Road to 56's own name for it (`rt56.counterparts`) is accepted only beside the vanilla name (`docs/stat-guide.md`). |
| `factSheet` | The section `## <key>` of `source/<pack>/fact-sheets.md` with the sourced facts behind the leader and his stats. |
| `portrait` | `photo`: a key of `photos.json`. `role`, `headwear`, `uniform`, `avoidHeadwear`, `notes` go into the portrait prompts as written; naming the headwear is what keeps it. An empty `headwear` is a warning of `-Check`, not an error. `born` and `photoYear`, four-digit years (the leader's birth year from the dossier, the photo's year from its record page; it also dates the photo for the own-work licence check): their difference is the age cue of the prompt, which keeps the painted face from coming out too young; either missing is a warning of `-Check`; a value that is not a four-digit year, a photo year before the birth year, or years that give an age outside 15 to 100 (the range the Manager's `-Age` takes) an error. Optional: `uniformColour`, a key of the Manager's `Scripts/Portraits/palettes.json` (`fin_army_m36_grey`, `fra_navy_blue`, ...; lower-case letters, digits and underscores), the cloth colour the Manager enforces before the repaint and names in the prompts; absent, the Manager's default for the tag and role applies. Optional, for a rejected round: `colourSeed`, a whole number from 0 up (absent: 1), the seed of the colouring step; `facePass`, `true` or `false` (absent: `true`), whether the face detail pass runs. `-Check` fails on any other value. |
| `reason` | `skip` only: why the leader is left out, with the id that already covers him. `-Check` fails when the reason names no character id of the snapshot. |

### Modes

- `new`: a character `<prefix>_<key>` in a `characters = { }` block [CHR-001], recruited from `on_startup` [CHR-003] [SCR-007] behind the `sameAs` guard. Each recruitment writes one warning line to `error.log` [CHR-014]. Works only in a new game [SCR-077].
- `addRole`: in `on_startup`, inside `if = { limit = { has_character = <target> } }`, the target gets the role and the large portrait, behind a guard on the role it already has: `is_army_leader` for an army role [SCR-103], `is_navy_leader` for a navy role [SCR-061]. The advisor role and its small portrait stay [CHR-013]. Road to 56 already makes some advisors leaders [RT56-011]; the guard skips them there.
- `skip`: nothing is generated. The leader stays in the file so that the research is not done again.

`-Check` compares each leader with the snapshot (`data/<pack>/game-characters.json`): a `new` leader's name or `sameAs` ids must not belong to a unit leader of vanilla or Road to 56; an `addRole` target must exist in vanilla with an advisor role and no unit-leader role of the same kind; every id in `sameAs` and `target` must exist in the snapshot.

## `source/<pack>/fact-sheets.md`

One section per leader, `## <key>`, with the facts behind the leader, his role and his stats, each with its source URL.

## `source/<pack>/workshop-intro.bbcode`

The opening of the pack's Workshop description in Steam BBCode. `-Generate` adds the leader list, a sentence that the portraits are repaints of period photographs under the photos' licences (no link to the wiki: the Workshop page carries no Wiki or GitHub links), and the cross-link block between the `<!-- cross-links:begin -->` and `<!-- cross-links:end -->` lines. The block is the Manager's, not this repository's: `Scripts/Workshop/Sync-WorkshopCrossLinks.ps1` of the Modding Manager writes it into each pack's description, and `-Generate` carries what is between the markers over unchanged.

## `source/<pack>/showcase.json`

Optional; the owner's approved text for the pack's Workshop gallery images. It changes only on the owner's word.

```json
{
    "leaders": {
        "<leader key>": {
            "card": ["<line>", "<line>", "<line>"],
            "years": [1896, 1986]
        }
    }
}
```

- `card`: 1 to 4 lines, each a restatement of a sourced bullet of the leader's fact-sheet section, one line of at most 160 characters.
- `years`: `[born, died]`, or `[born]` for a man whose death year the fact sheet does not give.
- A leader without an entry gets a card with role, birth year (`portrait.born`), stats and traits only, and `-RenderShowcase` warns about it.

`-Check` fails on a key that is not a leader or is a `skip` leader, on an unknown field, and on an empty, broken or fifth line. It warns when `years` starts with another year than `portrait.born`.

`build.ps1 -RenderShowcase [-Pack <pack>]` draws the images with the Manager's `Scripts/Showcase/New-HoiShowcaseImage.ps1` (skill `hoi4-workshop-showcase`) into the git-ignored `artifacts/workshop-images/<pack>/`, with the spec it built beside them:

- **`00-roster.png`:** every leader that is not `skip`. It splits into pages of 10 as `00-roster-1.png`, `00-roster-2.png` and so on.
- **One card per leader:** `NN-<key>.png`, in `leaders.json` order.
- **Role:** "General" in green, "Field marshal" in brass, "Admiral" in blue.
- **Stats:** the skill, then the four attribute skills of the role kind, with the game's icons.
- **Traits:** with their game names and icons, leaving out the Road to 56 counterpart traits of `data/<pack>/start-traits.json`.
- **Credit line:** "AI-assisted repaint", with the author and licence of a CC BY photo.
- **Background and flag:** the loading screen of `background` in `assets/thumbnail.json`, and the pack's flag in its 1936 variant.

The owner uploads the images on the Workshop page by hand ("Add/edit images & videos").

## `source/<pack>/photos.json`

Written only by `build.ps1 -FetchPhoto` and `-ConfirmLicence`. The licence gate is the Manager's shared `tools/HoiImageSources.ps1` (a synced copy; never edit it here), called with this mod's policy: public domain with its stated reason, CC0, CC BY, or CC BY-SA 2.0 or later (ported versions such as `3.0 de` included; 1.0 and IGO refused), at least 300 px on the shorter side.

### Photo sources

| Source | Command | Licence read from | Id |
|---|---|---|---|
| `commons` | `-FetchPhoto -Pack <pack> -File "File:<title>" -Key <key>` | the Commons API: licence code, `PD-` templates, deletion and dispute templates, `Attribution` | the `File:` title |
| `finna` | `-FetchPhoto -Pack <pack> -Source finna -Id "<record id>" -Key <key>` | the Finna API: `imageRights` of the record and of its image | `sa-kuva.sa-kuva/111307` |
| `europeana` | `-FetchPhoto -Pack <pack> -Source europeana -Id "<item id>" -Key <key>` | the Europeana record API: `edmRights` of the record and of its image | `/91616/arme_photo_AMA0013571` |
| `manual` | `-FetchPhoto -Pack <pack> -Evidence scratch\evidence-<key>.json -Key <key>`, then `-ConfirmLicence -Pack <pack> -Key <key>` on the owner's word | a rights sentence quoted from the archive's page, which the tool finds on the page, and the owner's confirmation | the record page address |

- Every fetch takes `-DryRun`, which records and keeps nothing. A Finna photo, whose size the API does not give, is downloaded and measured even in a dry run, then dropped.
- `build.ps1 -FindPhoto -Query "<name>" [-Source commons,finna,europeana] [-Limit 10]` searches the three APIs and prints each hit with the gate's verdict: `ACCEPTABLE`, `ACCEPTABLE, size checked at download` or `REFUSED` and why. Its Year column is the earliest year in the record, which dates an own-work claim; it is not always the year the photo was taken.
- Europeana needs a free API key (from `https://pro.europeana.eu/page/get-api`): the environment variable `HOI_EUROPEANA_WSKEY`, or `{ "keys": { "europeana": "<key>" } }` in the Modding Manager's git-ignored `Config/image-sources.local.json`. The key goes in a request header, never into a record or an address.
- Public domain on Finna and Europeana is the Public Domain Mark, recorded as `PDM (<institution>)`; `NoC-US (<institution>)` is public domain in the United States only and warns like `PD-US`.
- The gate refuses: a licence outside the policy (NC, ND, In Copyright, not evaluated); a record whose image has other rights than the record; CC BY or CC BY-SA without a named author or an institution to credit; an "own work" claim (Commons `PD-self`, `{{Own}}`, `{{Self}}` or an "Own work" credit) on a photo whose earliest known year, the leader's `photoYear` included, is before 1960; a file that is not a picture; a download off the source's servers; a photo under 300 px on its shorter side.
- A manual evidence file holds `recordUrl`, `imageUrl` and `rightsUrl` (all https), `rightsQuote` (the sentence that grants the licence, word for word, at least 40 characters), `license` (`pd`, `cc0`, `cc-by-4.0`, `cc-by-sa-4.0`, ...), `publicDomainReason` (for `pd`), `author`, `institution`, `credit`, `dateOriginal` and `title`. The tool fetches the rights and record pages, turns them into text, and finds the quote in the rights text, else in the record text, with spaces, quotes and dashes made plain. It writes the two texts to `source/<pack>/evidence/<key>.rights.txt` and `<key>.record.txt` (committed; only `-FetchPhoto` writes them).

### Rows

The download is kept in `sources-cache/<pack>/<key>.<ext>` (git-ignored). A request answered with 429 or 503 is tried again up to five times in all, waiting 5, 10, 20 and 40 seconds, or longer when its `Retry-After` asks (at most 120), and prints the server's own message each time. The User-Agent names the repository as its contact, as Wikimedia's User-Agent policy asks.

Each row keeps `key`, `source` (absent in rows written before 2026-11-03: `commons`), `sourceId`, `commonsTitle` (Commons rows), `title`, `pageUrl`, `downloadUrl` and its `downloadSha256`, `institution`, `author`, `credit`, `attribution` (the credit line: the licensor's own attribution, the named author, or the institution), `licenseShortName`, `license` (a code such as `cc-by-sa-3.0-de`), `licenseCategory` (`PD`, `CC0`, `CC BY`, `CC BY-SA`), `licenseUrl`, `rightsUri` (the source's raw rights value), `usageTerms`, `restrictions`, `dateOriginal`, `pictureYear` (the earliest year in the record), `ownWorkClaim`, `width`, `height`, `fetched` and `publicDomainReason`. A manual row adds `evidence` (the three addresses, the quote, `quoteFoundIn`, the SHA-256 of each page text, the capture date) and `ownerConfirmed` (`""` until `-ConfirmLicence` writes the date and a hash of the evidence, the download and the licence; a new fetch resets it).

`-Check` derives the licence category from the recorded code again, checks each source's page and download addresses, compares the hash with the cached download when it is there, and for a manual row checks the page captures against their hashes and the owner's confirmation: unconfirmed or changed is an error for a photo a leader uses, a warning for one no leader uses. `-MakePortraits` refuses an unconfirmed manual photo. `-Audit` reads every licence from its source again (a manual photo: looks the quote up on the archive's page again) and warns about one read more than 180 days ago; a photo its source now refuses is an error when a leader uses it, a warning otherwise.

A portrait painted from a CC BY-SA photo is an adaptation licensed CC BY-SA 4.0: the wiki page says so in its row and above the table, the Workshop description names those leaders, and the showcase card's note starts `Portrait (CC BY-SA 4.0)`. A pack whose photos all come from Commons, without CC BY-SA, generates the same wiki and Workshop text as before these sources existed.

## `source/<pack>/portraits.json` and `source/<pack>/portraits/<key>.png`

Written only by `-MakePortraits`, `-ApplyPortraitReview` and `-RefinishPortraits -Apply`. One entry per leader:

```json
{
    "leaders": {
        "einar_vihma": {
            "rounds": [
                {
                    "round": 1,
                    "date": "2026-11-01",
                    "seeds": [1, 2, 3, 4],
                    "settings": { "role": "Finnish general", "headwear": "...", "uniform": "...", "avoidHeadwear": "...", "notes": "", "uniformColour": "", "colourSeed": 1, "facePass": true, "born": 1894, "photoYear": 1943, "age": 49, "ageSent": true },
                    "run": "C:\\dev\\Hearts of Iron IV Modding Manager\\Artifacts\\portraits\\lp_fin_einar_vihma\\round-1\\portrait-run.json",
                    "recipe": { "steps": [ { "template": "K1", "sha256": "..." }, { "template": "M1", "sha256": "..." }, { "template": "A4", "sha256": "..." }, { "template": "F2", "sha256": "..." } ], "facePass": true, "finish": { "style": "style-FIN.json", "styleCount": 37, "detailStrength": 0.25, "toneStrength": 0.8, "chromaStrength": 0.75 }, "framing": { "eyeCentreX": 402.1, "headCentreX": 455.0, "centreBlend": 0.5, "headTop": 12.0, "photoClipsCrown": false, "headroom": 0.02, "faceHeight": 0.49 }, "uniformColour": { "key": "fin_army_m36_grey", "name": "field grey", "lab": [48, -1, 2], "default": true, "applied": true, "before": [41.2, 0.3, 5.1], "after": [44.6, -0.9, 2.2], "deltaE": 3.5, "reason": null } },
                    "candidates": [ { "seed": 1, "file": "...\\final\\A4_s1.png", "sha256": "...", "likeness": 0.51 } ],
                    "decision": { "pick": 2 }
                }
            ],
            "chosen": { "round": 1, "seed": 2, "file": "source/finland/portraits/einar_vihma.png", "sha256": "...", "refinished": { "date": "2026-11-03", "run": "...\\round-1\\refinish-1\\refinish-run.json", "candidateSha256": "..." } }
        }
    }
}
```

- `-MakePortraits -Pack <pack> [-Leader <key>] [-StartComfyUI]` makes one new round of 4 candidates for every `new` and `addRole` leader that has no `chosen` portrait, through the Manager's `New-HoiPortrait.ps1` (skill `hoi4-leader-portraits`) with the photo's cached download and the `portrait` fields; `born` and `photoYear` go as `-Age`, their difference, when both are set and the Manager's script takes the parameter; a Manager without it gets a `[WARN]` line and no age; `uniformColour` goes as `-UniformColour` the same way. The round's `settings` keep `born`, `photoYear` and `age` (`null` when unknown) and `ageSent`, whether the age reached the Manager. The recipe steps and candidate file names are whatever the Manager's recipe of the day writes (`A4_s1.png` since its round 6 recipe). The seeds of round `n` are `4n-3` to `4n`. With `-StartComfyUI` it starts ComfyUI once for the whole batch and stops it at the end, also after an error; a ComfyUI it did not start is left running.
  - `-Leader <key>` makes a round for that leader only, also when he has a `chosen` portrait already; a later pick replaces it.
  - A leader whose latest round has no decision yet is skipped (with `-Leader`, exit 1): the owner reviews first.
- `-ApplyPortraitReview -Pack <pack> -Leader <key> -Pick <seed>` records the owner's pick on the latest round and copies that candidate to `source/<pack>/portraits/<key>.png` with its SHA-256. `-Reject "<reason>"` records the rejection on the latest round; the reason is what the next round must change. A round that has a decision cannot be decided again; a new round can.
- `-ApplyPortraitReview -Pack <pack> -Leader <key> -Withdraw "<reason>"` withdraws the record of a leader who has left `leaders.json`, so that nothing made from his photo is committed: it deletes `source/<pack>/portraits/<key>.png`, sets `chosen` to `null` and writes `withdrawn` on the latest round, whose decision and candidates stay as history. It refuses a key still in `leaders.json` (in any mode), a latest round that waits for its decision, and a record withdrawn already. `-Check` warns about a record whose key no leader has until it is withdrawn, and is silent about it afterwards. A leader who comes back gets a new round from `-MakePortraits -Leader <key>`; the withdrawn round stays in his history.
- `-RefinishPortraits -Pack <pack> [-Leader <key>] [-StartComfyUI]` runs the Manager's finish stage (`New-HoiPortrait.ps1 -Refinish`: skin tone, photo detail, the vanilla backdrop) on the chosen candidate of every leader with a `chosen` portrait, from the round folder's saved `face-pasted/A4_s<seed>.png` (or `paint/` without the face pass) and `photo.png`, beside the chosen PNG as it is. With ComfyUI running, or `-StartComfyUI` (started once for the batch and stopped at the end), the Manager masks each candidate itself, which is what the finish needs: the repaint extends a shoulder into the frame's padded edge where the photo's mask stops. Without ComfyUI the round's `mask/M1_s1.png` is used instead, with a `[WARN]` naming the leaders, and the plan's `maskSource` says `photo`. It writes `scratch/refinish/<pack>/refinish.json` (per leader: the refinished file, its SHA-256, the chosen SHA-256 it was made for, the likeness and the finish numbers before and after) and `scratch/refinish/<pack>/sheet.png` (the shipped row and the refinished row at the game's sizes; no vanilla image is on it, the owner compares in the game), and changes nothing else. The candidate file is named after the round's `recipe.paintTemplate` (`A4` for a round without it). A leader whose round folder is gone is skipped with the advice to make a new round, which gets the finish by itself. Centring is not redone: the frame was generated before the head-mass centring existed.
  - `-RefinishPortraits -Pack <pack> -Apply [-Leader <key>]`, on the owner's word after the sheet, copies each refinished file over `source/<pack>/portraits/<key>.png`, sets `chosen.sha256` to the new file and writes `chosen.refinished`: `{ "date", "run" (the Manager's `refinish-run.json`), "candidateSha256" (the SHA-256 of the candidate as it was picked, which `-Check` compares with the round's candidate) }`. It refuses a leader whose chosen portrait changed since the refinish was made, and a refinished file that is gone or changed. `-Check` requires the `run` and a `yyyy-MM-dd` `date` on the record; the run file itself lives in the Manager's git-ignored artifacts and cannot be checked from the repository, so the record is the owner's word that the finish, not a hand edit, made the file. `-ConvertPortraits` then rebuilds the DDS files, because the chosen SHA-256 changed. A second refinish keeps the first `candidateSha256`.
- The record's shapes:
  - `decision` is `null` while the round waits, `{ "pick": <seed> }` or `{ "reject": "<reason>" }`.
  - `withdrawn` is absent, or `{ "date": "<yyyy-MM-dd>", "reason": "<reason>" }` on a decided round. A record is withdrawn while its latest round has it; `chosen` is then `null`.
  - `chosen` is `null` until the first pick, and again after a withdrawal. `chosen.refinished` is absent until `-RefinishPortraits -Apply`.
  - `recipe` carries what the Manager's run record says: `steps`, `facePass`, `finish` (`null` from a run without the finish stage, or from a Manager older than 2026-11-03), `framing` (the second crop's numbers, `null` without the head-mass centring) and `uniformColour` (`null` for a tag without a palette default and no `uniformColour` field). Rounds made before 2026-11-03 carry `gradeStrength` instead.
  - `run` and each candidate's `file` are absolute paths in the Manager's `Artifacts/portraits/<prefix>_<key>/round-<n>/` (git-ignored, on the machine that made them). The Manager numbers its `round-<n>` folders by itself; the pack's `round` is the one that counts, and the two can differ.
- The chosen PNG is committed: generation is not reproducible across ComfyUI versions and GPUs.

## `source/<pack>/review.json` and the review page

The owner decides a round on a published review page rather than in the chat. `build.ps1 -ReviewPage -Pack <pack>` writes `scratch/review/<pack>/portrait-review.html` (git-ignored) from `tools/review-page-template.html` and `tools/review_page.py`, with one section for each leader whose latest round has no decision: the photo, the coloured photo, the previous round's decision, and the 4 candidates at the game's 156x210 and at three times that. With no round to review it writes nothing and exits 0.

- The agent publishes the page with the Artifact tool, with the capabilities the command prints: `{"db": {"rules": [{"path": "reviews", "read": "view", "write": "owner"}]}, "user": {}}`. Only the owner can decide; anyone the page is shared with can look.
- The first publish of a pack is recorded with `-ReviewPage -Pack <pack> -PageUrl <claude.ai artifact URL>`, which writes `source/<pack>/review.json`:

```json
{ "pageUrl": "https://claude.ai/artifact/...", "recorded": "2026-11-01" }
```

- Later rounds republish to the same URL, so the owner keeps one bookmark per pack.
- Each decision is a document of the page's `reviews` collection, named `<leader key>-r<round>`:

```json
{ "leader": "einar_vihma", "round": 1, "decision": "pick", "seed": 2, "reason": "", "decidedAt": "2026-11-01T12:00:00Z" }
```

  `decision` is `pick` (with `seed`, `reason` empty) or `reject` (with `reason`, `seed` null). The agent reads the collection with ArtifactData and applies each document with `-ApplyPortraitReview`, so `portraits.json` stays the record; the page only carries the owner's choice.
- Without the page's database the owner copies the decisions from the page as text lines, `<key> round <n>: pick <seed>` or `<key> round <n>: reject "<reason>"`.

## `source/<pack>/converted.json`

Written only by `-ConvertPortraits -Pack <pack> [-Force]`: for each DDS of the pack, what it was built from.

```json
{
    "portraits": {
        "gfx/interface/ideas/lp_fin_einar_vihma_small.dds": { "leader": "einar_vihma", "kind": "small", "chosenSha256": "...", "cardSha256": "...", "ddsSha256": "..." },
        "gfx/leaders/FIN/lp_fin_einar_vihma.dds": { "leader": "einar_vihma", "kind": "large", "chosenSha256": "...", "cardSha256": "", "ddsSha256": "..." }
    }
}
```

- `chosenSha256` is the chosen PNG's SHA-256 from `portraits.json`; `cardSha256` the SHA-256 of `data/portrait-card.json` with its line ends as LF (small cards only); `ddsSha256` the DDS as written.
- `-ConvertPortraits` skips a DDS whose three hashes are current, and converts it again with `-Force`.
- `-Check` fails on a DDS that is missing or of the wrong size, has no record, differs from its recorded hash, or was built from another chosen PNG or another card file; and on a record of a DDS no leader has.
- The small card needs the Modding Manager and the ComfyUI venv of its `Config/comfyui.json`: the crop of the photo window runs the Manager's `Measure-PortraitFaces.py crop` there. Without them `-ConvertPortraits` converts the large portraits and ends with exit 1.

## `data/`

| File | Content |
|---|---|
| `data/<pack>/game-characters.json` | Written by `-RefreshGameData -Pack <pack>` (needs the game): the country's characters in vanilla and in Road to 56, with ids, names, roles and slots. `-Check` and CI read this file, never the game. Refresh it before each release [RT56-011]. |
| `data/<pack>/start-traits.json` | Written by `-RefreshGameData -Pack <pack>`: per role kind (`army`, `navy`), every trait a vanilla unit leader of that kind has at the start in any country, except a trait named after a country (an upper-case prefix such as `JAP_`), which is kept only when a character of the pack's own tag has it. Under `rt56`, from the trait definitions read with and without Road to 56: `undefined`, the start traits vanilla defines and Road to 56 does not; `counterparts`, for such a trait the one unit-leader trait that only Road to 56 defines and whose name holds the trait's name (`jaeger` to `jaeger_trait`), where exactly one does. |
| `data/stat-bands.json` | Hand-written: the start ranges of `skill` and the attribute skills per role kind [CHR-006] [CHR-012]. |
| `data/workshop.json` | The wiki address, shared by every pack. |
| `data/portrait-card.json` | The small card's geometry and the face position inside its photo window [CHR-005]; read by the converter. The owner approved these values: they change only on the owner's word. |

`game-characters.json`, `start-traits.json` and `portrait-card.json` are protected from hand edits by the project hook.

## `assets/thumbnail.json`

The spec of the Workshop thumbnails, read by the Manager's `Scripts/Showcase/New-HoiThumbnail.ps1` (skill `hoi4-workshop-showcase`, whose reference lists every field). `version` is 1. The top-level `background`, shared by every pack, is `gamePath` (a loading screen's path under the game root, read at render time and never copied into the repository), `crop`, `blur` and `scrim`; `-RenderShowcase` draws the gallery images over the same `gamePath`, `crop` and `blur`. Per pack, `packs.<pack>.portraits` lists up to 4 chosen portraits as `source/<pack>/portraits/<key>.png`, left to right; the release skill writes them on the owner's word. The title, the country, the flag (the pack's `tag` in its 1936 variant), the layout and the colours come from the tool. The file changes only on the owner's word.

# Leader Pack: release a pack

Each pack is its own Workshop item, and the bundle "Immersive Commanders Expanded" (package `all`) holds all of them: a pack's upload also uploads the bundle in the same run. The agent cannot load the shared `hoi4-mod-release` skill: first ask the owner to run `/hoi4-mod-release` in this session, and do not read its file instead. Once the owner has run it, work from both skills: follow its sections "Repos with packages" and "A pack that belongs to a bundle", with these additions. Every command names the package: `-Pack <pack>`, or `-Pack all` for the bundle alone.

**Release in waves.** A new country ships its Event Pack and its Commanders Pack in the same session, so the four items (two packs, two bundles) are touched together: each change note names the leaders of the pack, and the bundles' change notes ("<Country>: <note>", the country added by `Publish-Mod.ps1`, so the owner types the note without it) are the announcement. The owner's launch posts link the two bundles and the collection rather than the single packs; draft their text on request. The Event Packs repository's `event-pack-release` skill has the other half.

## 1. Preflight
1. The pack's last plan is `DONE` and shipped (archived and committed), and its game check is recorded in the plan's "Outcome" (`leader-pack-implement` section 4). A pack without a game check waits for one, on the owner's word.
2. `powershell -NoProfile -File "<Manager root>\Scripts\Publish-Mod.ps1" "Leader Packs" -Pack <pack> -PreflightOnly`. Done when no row is FAIL. Once the bundle has a `remote_file_id` the table also holds the `Bundle:` rows (validation, description size, Workshop text, content changes); `Bundle: Unreleased member changes` FAIL means another released pack has committed changes since its own last tag: release that pack first, or wait. Before the bundle has an id a WARN row says it is not yet published and only the pack goes up.
2b. `powershell -File .\build.ps1 -Check -Pack all` ends `Check OK`: the pack is a member, the bundle page names it and carries the portrait licences of every member, `source/all/workshop-intro.bbcode` names it.
3. `powershell -File .\build.ps1 -Audit -Pack <pack>`: no `[ERROR]`. A `[WARN]` that a photo's licence was last read over 180 days ago: fetch it again for real with the command of its `source` (`-File "<its commonsTitle>"`, or `-Source <source> -Id "<its sourceId>"`; `docs/source-format.md`, "Photo sources") and `-Key <its key>`, then `-Check -Pack <pack>`, and commit before the release; a `REJECTED` stops the release and goes to `leader-pack-audit`. A manual photo is not fetched again here: the audit has just looked up its quote on the archive's page, and an `[ERROR]` that the owner has not confirmed it stops the release. A `[WARN]` that a used photo's source or archive page could not be read means its licence was not read again: run the audit again later, and do not release until it reads.
4. The snapshot is current: `data/<pack>/game-characters.json` was refreshed after the last Road to 56 update the owner installed (its `refreshed` date). If not, run `leader-pack-audit` Phase 1 first [RT56-011].
5. `powershell -NoProfile -File "<Manager root>\Scripts\Knowledge\Test-HoiKnowledge.ps1" -Repo leader-packs -Detailed` (the `hoi4-modding-knowledge` skill): no blocking finding, and none of the files this release changed is in the sweep queue (a queue left by other work is only a WARN of the preflight).

## 2. Thumbnail
A pack with fewer than 2 portrait paths under `packs.<pack>.portraits` of `assets/thumbnail.json` (its `-NewPack` thumbnail shows the flag only, or the plain `assets/thumbnail_master.png` when the Manager was not found) gets its own thumbnail before its first upload; with fewer than 2 chosen portraits the release stops and the owner is told. A pack that has its portraits keeps its thumbnail unless the owner asks, or a leader it shows has had a new portrait picked since: a recorded `source/<pack>/portraits/<key>.png` whose last commit (`git log -1 --format=%cI -- <file>`) is newer than that of `packs/<pack>/thumbnail.png`.

Every pack's thumbnail is drawn by the Manager's `New-HoiThumbnail.ps1` (skill `hoi4-workshop-showcase`) in the one Commanders Pack layout: `COMMANDERS PACK` in the plate at the bottom with the country under it, the flag at the top right, the pack's portraits in a row, over the shared loading screen of `assets/thumbnail.json`. The tool fixes the layout, the colours and the flag; a pack chooses only its portraits.

1. The portraits: the paths under `packs.<pack>.portraits` of `assets/thumbnail.json`. A pack without them: propose its 3 best-known leaders with a chosen portrait (2 when it has only 2), in the order they are to stand left to right, and on the owner's word, which may swap them, write them there as `source/<pack>/portraits/<key>.png`, in that order.
2. Preview: `powershell -NoProfile -File "<Manager root>\Scripts\Showcase\New-HoiThumbnail.ps1" "Leader Packs" -Pack <pack>`. Its line ends with `new`, `changed` or `unchanged` against the committed file and the preview's path under the Manager's `Artifacts\thumbnails\leader-packs\<pack>\`; a `Warning:` line is fixed in the data, not accepted. Look at the preview with the Read tool, then show it to the owner.
3. On the owner's word, run the same command with `-Apply`: it writes `packs/<pack>/thumbnail.png`. The loading screen, the flag and the game's frames, plates and fonts it draws are read from the game install at render time and ship only inside that file. Never copy, convert or save any of them anywhere else; the gallery images of section 2b stay git-ignored under `artifacts/`.
4. `powershell -File .\build.ps1 -ValidateOnly` ends `Validation succeeded.`, then commit the thumbnail, and `assets/thumbnail.json` when its portraits are new, on the owner's word.

## 2b. Gallery images
1. Every leader the release adds has card lines in `source/<pack>/showcase.json` (`docs/source-format.md`). A leader without them: propose 3 or 4 lines and the years from his fact-sheet section, and write them only on the owner's word.
2. `powershell -File .\build.ps1 -RenderShowcase -Pack <pack>` writes the roster and one card per leader to `artifacts/workshop-images/<pack>/`. A `Warning:` line (a text cut short, a missing sprite or flag) is fixed in the data, not accepted. Look at every image, then show them to the owner.
3. After the upload of section 4, the owner adds or replaces them on the pack's Workshop page ("Add/edit images & videos"); the upload carries only the thumbnail. The bundle page has no leader cards of its own. Its gallery is the folder `<Manager root>\Artifacts\bundle-gallery\Immersive Commanders Expanded\` (git-ignored, filled by hand: no script writes it), named in upload order: `01-cover.png` is a copy of `<Manager root>\Artifacts\branding\immersive-commanders-expanded-cover.png` (drawn by `Export-HoiBrandingShowcase.ps1`), then `02-<country>-roster.png`, one per member in alphabetical country order, each a copy of `artifacts/workshop-images/<pack>/00-roster.png` of this repository. When a member joins or its roster changes, copy the file in (a new country renumbers the files after it), give the owner the folder's full path and have them replace the bundle's gallery the same way: remove the old images, upload in name order.

## 2c. Description images
The generated description has a `hero` and an `overview` region, and the preflight's Workshop text row fails a first upload while either has no address in the Manager's `Config/workshop-image-urls.json` (`commanders-pack-<country>/hero` and `/overview`; the strips are shared by the family and exist).
1. `powershell -File .\build.ps1 -RenderShowcase -Pack <pack>` first (section 2b): the overview is drawn from its files.
2. `powershell -NoProfile -File "<Manager root>\Scripts\Showcase\Export-HoiDescriptionImages.ps1" "Leader Packs" -MissingOnly` writes the images that have no address yet (both of the new pack) to the Manager's `Artifacts\description-images\`. Look at them, then show them to the owner.
3. The owner uploads them to Imgur and gives the addresses; add them to `Config/workshop-image-urls.json`, run the Manager's `Sync-WorkshopRegions.ps1 "Leader Packs"` and `Sync-WorkshopCrossLinks.ps1` (the "More from the author" block carries the series banner and lists the series), and commit the Manager and this repository on the owner's word.

## 3. Change note, credits and description
1. The change note names the leaders added or changed, by name, and any leader set to `skip` with the reason.
2. The photo credits are on the pack's wiki page (`wiki/Commanders-Pack-<Country>.md`, generated), which the Workshop description does not link to (it carries no Wiki or GitHub links): run `powershell -File .\wiki\push-wiki.ps1` before the upload, so the page is live and complete.
3. The description on Steam is the generated `packs/<pack>/WORKSHOP_DESCRIPTION_GUIDELINES.md`. Check that it holds the sentence that the portraits are repaints of period photographs under the photos' licences: that licence statement is never removed or shortened, and no sentence about how the portraits were made beyond it is added. When the Event Packs repository (`../event-packs/packs/<country>/descriptor.mod`) has a published pack for the same country (`remote_file_id` set), check that the description links it right after the opening sentences as a `[h2]Companion mod: ...[/h2]` line, with the name and id of that descriptor; a missing or stale link is added to `source/<pack>/workshop-intro.bbcode` and the pack generated again (`-Generate -Pack <pack>`, then `-Check -Pack <pack>`). The Companion mod line of the bundle: once the Event Packs bundle "Immersive Events Expanded" is published (`remote_file_id` in `../event-packs/packs/all/descriptor.mod`), `source/all/workshop-intro.bbcode` may name it the same way (`[h2]Companion mod: ...[/h2]` with the name and id read from that descriptor); with no published Events bundle there is none. The bundle's page text is generated and changes only through `source/all/workshop-intro.bbcode`, then `-Generate -Pack all` and `Sync-WorkshopRegions.ps1`. A first upload, or a description changed since the pack's last tag (the latest of `git tag --list "workshop-<pack>-*"`, a same-day release has `-2`, `-3`; `git diff <tag>..HEAD --stat -- packs/<pack>/WORKSHOP_DESCRIPTION_GUIDELINES.md`), takes `-UpdateDescription`.

## 4. Upload and tag
1. `Publish-Mod.ps1 "Leader Packs" -Pack <pack> -DryRun -ChangeNote "<note>"`: show the owner both VDFs it prints (a dry run exits 0 even with a FAIL row in the table above it, so it counts only after the preflight shows none). The pack's: title `Commanders Pack: <Country>` and the file list (only that pack's `common`, `interface`, `gfx` and `localisation`, its descriptor and thumbnail). The bundle's (once it has an id): title `Immersive Commanders Expanded`, the change note "<Country>: <note>", and the file list of every released member plus the pack of this run, with the bundle's own descriptor and thumbnail. A member that is not released yet is not in it.
2. Give the owner the upload command for their own terminal: `powershell -NoProfile -File "<Manager root>\Scripts\Publish-Mod.ps1" "Leader Packs" -Pack <pack> -ChangeNote "<note>"`, with `-UpdateDescription` per step 3.3. The bundle's description goes up by itself when its text changed since its last tag. If the second upload fails, the run exits 1 after tagging the pack, says which item went up and prints the command that uploads the bundle alone (`-Pack all`).
3. A first upload writes the new id into `packs/<pack>/descriptor.mod`: ask the owner to commit it. The command tags `workshop-<pack>-<date>` and, for the bundle, `workshop-all-<date>`; pushing the tags is the owner's call. After the run, `Test-ModWorkshopListing.ps1 "Leader Packs"` shows OK for the pack and for the bundle.
4. A new pack's first upload (no `remote_file_id` before the run) is a wave, not one command: its new id is missing from the "More from the author" list of the other published packs and of its own page (its first upload carried a list without itself) until they are uploaded again. The preflight says so before the run (a `Pages stale after upload` WARN row, the steps under its table, printed again after the upload); the bundle's page is not affected. Carry it out in the same session: (a) the owner commits `packs/<pack>/descriptor.mod`; (b) run `powershell -NoProfile -File "<Manager root>\Scripts\Workshop\Sync-WorkshopCrossLinks.ps1" "Leader Packs"` and commit the pages it changed on the owner's word; (c) give the owner one `Publish-Mod.ps1 "Leader Packs" -Pack <pack> -SkipBundle -UpdateDescription -ChangeNote "Description refresh"` per page the preflight listed, the new pack included (such an upload adds no entry to the Workshop change notes [WS-007]); (d) `Sync-WorkshopCrossLinks.ps1 -Check` (no mod name) says Current; it reads the files, so the wave is done when every command of (c) has run.
5. Remind the owner to add the new pack's item to the Steam collection "The Immersive Series: Commander Packs" (collection 3834987626) by hand; the bundle stays out of it, it belongs to the main collection. The collection text and its banner then name the pack: `Test-WorkshopText.ps1 -Collection commander-packs` fails until the Manager's `docs/workshop-collection-commander-packs.bbcode` links it, and `Export-HoiBrandingShowcase.ps1` redraws the banner (the Manager's `hoi4-workshop-description` skill).

## 5. The bundle's first release
Only on the owner's word, and only after the in-game check of the bundle is recorded: the owner has reported the result, it is in the Manager's register (`Add-HoiKnowledge.ps1`), and the bundle's row has left the Manager's `docs/ingame-verification-pending.md`. That is so for the same-release loads [LOAD-022]; the check of a pack of another release beside the bundle waits for the next real pack release and does not gate the first upload.
1. `Publish-Mod.ps1 "Leader Packs" -Pack all -PreflightOnly`, then `-Pack all -DryRun -ChangeNote "<note>"`: it ships the released members only; show the owner the VDF and the file list. Until step 2 is done the Workshop text row is FAIL for the missing images, which is expected.
2. The owner runs the first upload with `-UpdateDescription`. The Workshop text row fails a first upload until the bundle's page images have addresses in the Manager's `Config/workshop-image-urls.json` (section 2c, for the key `immersive-commanders-expanded/hero` and the shared `commanders-bundle/strip-*` strips). The same row fails while the page lacks its cross-link block: `Sync-WorkshopCrossLinks.ps1 "Leader Packs"` writes it into the bundle page before the id exists (it is covered only when the mod is named), and commit.
3. `Set-ModWorkshopTags.ps1 "Leader Packs" -Pack all` sets the tags [WS-001]; the owner makes the item public.
4. `Test-ModWorkshopListing.ps1 "Leader Packs"` shows OK. Ask the owner to commit `packs/all/descriptor.mod` (it now has the `remote_file_id`). Then `Sync-WorkshopCrossLinks.ps1` names the bundle on every page, and the collection text puts it first in its section (the Manager's `hoi4-workshop-description` skill).
